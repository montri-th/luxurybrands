# CityMETER Luxury Brands — owner preferences

Reaffirmed 2026-10-22 (release 0.4).

- Apply current LDS 0.9.7 (v0.9.7-owner.1, standalone-0.9.7-r1) and preserve the map-first CityMETER layout. Colours come only from `assets/theme.css` and `js/scales.js`; never approximate a value by eye.
- Aha first, in 3D: the first paint is the city preset (pitch 56°, bearing 28°) framing the top three neighborhoods, which are focused automatically (`auto` focus mode, no `areas` param). Show one computed spatial finding (share of brands in those areas), its numerator and denominator, the 3D map cue and the immediate actions (ดูทุกย่าน, เปรียบเทียบย่าน) before complex filters. No onboarding gate. Snapshot numbers in the handoff JSON are fixtures, not UI constants.
- The product statement is a winning strategy (Who / What / Which / How per MBB v0.5.3 §7.2 and PB v6 §1.6) — read `PRODUCT_STATEMENT.md` before changing what the first screen argues; every product change should serve its quality bar.
- Focus + quiet context (owner instruction 2026-10-22): draw detail only for the focused part — the selected neighborhood, the explicit or automatic focus areas, or everything only when the user asks for ดูทุกย่าน (`?areas=all`). Everything else stays visible but quiet: outline-only areas, quiet labels, grey context dots without logos and outside the tab order, city massing in the quiet tone.
- Basemap and massing are context, never data: colours come only from the `--basemap-*` tokens in `assets/theme.css`; the style is generated by `js/map-style.js` (no hosted style URL); building heights come from OpenFreeMap/OSM tiles and are never quoted as dataset facts; focus-tier rounding and enclosure (`js/geometry.js`, `js/massing.js`) are display-only. Host buildings (`js/buildings.js`) remain the only building layer with a data colour.
- Camera presets (`js/camera.js`) never move or scale data: `city` for the overview, `model` (FOV 14°) for a neighborhood, `eye` (มุมสถาปนิก, two-point: pitch 75 / FOV 24) at venue level only — on by default there (venue mode, or a store inside a venue; `?cam=model` opts out), never elsewhere — and `plan` when 3D is off. Keep every 3D preset at pitch ≤ 90° − fov/2 − 3°: MapLibre 5.6.2 draws fill-extrusion displaced or not at all once the horizon enters the viewport (verified live 2026-10-22). A venue is framed on its host building(s) with every footprint vertex inside the padded viewport.
- Venue level is a focus of its own (owner decision 2026-10-22): only the venue's rows carry detail — its host building is the only blue one, other venues' buildings fall back to quiet massing, their pins to grey context dots. The venue's own mass must be visible and clickable at any pan, pitch or zoom (owner 2026-10-22, second round): the host extrusion is installed before every massing tier (MapLibre depth order = draw order; translucent extrusions still write depth) and `js/venue-xray.js` draws the venue solid on top of the 3D pass with a scissored depth clear; clicks stay on the style layer. Never reorder these layers casually. In the eye scene the surrounding massing goes very quiet (`SCENE.eye` opacities) and focus-tier buildings standing between the camera and the venue become see-through (`massing.setScene`, screen-space occlusion test on `moveend`). The city tier is always nearly transparent (0.22) and fades to the ground tone with distance from the focus anchors (feature-state `fade`, 500 → 2200 m).
- Country view (owner 2026-10-22): with the whole country on screen the provinces that hold brands get frames (`data/provinces.geojson`, OpenGISData-Thailand CC BY 4.0, DOPA-credited) filled by their own count classes below zoom 9, outlines to zoom 12, ink-chip labels and a panel list — each a drill-down into the จังหวัด filter. Frames are navigation context, never an administrative claim.
- Pictograms (owner test exception 2026-10-22): metric tiles, section headings and province chips may use the 8-glyph Material Symbols Rounded pictogram subset (`PICTOGRAM_CONTRACT`); the text label stays the meaning, the nav-7 approved subset stays byte-identical, and the exception is retired once LDS registers the set.
- Breadcrumb is ประเทศไทย › จังหวัด › ย่าน › สถานที่ with the production province codes in `js/model.js#PROVINCES` and the CityMETER Shopping Center id as the venue id; the ย่าน crumb comes from point-in-polygon on the venue's representative point (a venue outside every core skips that level); a store is the panel heading, never a crumb; never invent a Locale or municipality id for a neighborhood core.
- Three row scopes are a contract: `rows` drive pins, counters and the table; `scopeRows` (filters before any area selection) drive the Aha denominator, the choropleth, the charts and the exclusive/shared reference. Say so in the UI whenever they differ.
- One marker always represents one observation; never aggregate stores. Logos are collision-managed with a ceiling of 250, only at zoom ≥ 14 and only inside the focus.
- Keep generic caveats and research workflow residue out of ordinary UI, popups, details, tooltips and help. Preserve provenance and methodology in source documentation. Preserve factual closure status, dates, sources, coordinate precision and actionable runtime errors; never replace uncertainty with fabricated facts; never show missing as zero.
- Use approved LDS Rounded outline navigation glyphs with FILL 0, weight 300, GRAD 0 and the asset optical size. Use a clear visible label when no approved glyph fits. The menu icon is for the mobile data sheet only.
- Copy (owner instruction 2026-10-22): short, natural Thai, no caveats on screen — แบรนด์ / สาขา (one point-of-sale record) / สถานที่ / ย่าน; units, provenance and limits live in the data section, help and docs. Metric tiles use the legend symbols instead of longer labels. Neighborhood labels are ink chips (`--area-label-*`) so they never look like brand logo boxes.
- Charts: matrix cells are equal in size; only the number and its count class carry meaning. No CSV download control. No decorative brackets or colored left rails. Review actual Thai and English at desktop and narrow widths in light and dark themes before claiming a change is done; local renders are not proof of a live release — run `npm run verify:live`.
