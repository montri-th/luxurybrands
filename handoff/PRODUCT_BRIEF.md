# CityMETER Luxury Brands — Product Brief

รุ่นส่งต่อ 0.2 · ปรับเอกสาร 22 ตุลาคม 2569 · ข้อมูลตรวจถึง 21 ตุลาคม 2569 · ใช้คู่กับ [product-brief.json](product-brief.json)

เอกสารนี้กำหนดประสบการณ์ที่ทีมพัฒนาต้องรักษาและต่อยอด ใช้ [PRODUCT_STATEMENT.md](../PRODUCT_STATEMENT.md) เป็นที่มาของเจตนาผลิตภัณฑ์ และใช้ brief ฉบับนี้เป็นสัญญาของหน้าจอรุ่นปัจจุบัน หาก machine contract กับเอกสารนี้ขัดกัน ให้ถือ JSON เป็นหลักและแก้ทั้งสองฉบับพร้อมกัน

## ผลิตภัณฑ์ช่วยตัดสินใจอะไร

**อ่านเมืองผ่านแบรนด์ — เห็นก่อนว่าแบรนด์กระจุกอยู่ย่านใด แล้วเจาะลงถึงศูนย์การค้า อาคาร และจุดขายพร้อมหลักฐาน** ผู้ใช้ต้องได้ภาพที่มีความหมายทันทีที่เปิดหน้า ไม่ต้องตั้งค่าตัวกรองก่อน และทุกการเจาะต่อต้องเห็นได้ว่ากำลังดูส่วนไหนของเมือง

| ผู้ใช้ | งานที่ต้องทำ | เส้นทางที่ผลิตภัณฑ์รองรับ |
|---|---|---|
| ทีมแบรนด์และขยายสาขา | จัดรายชื่อย่านและสถานที่สำหรับสำรวจ | ภาพรวมย่าน → โปรไฟล์ย่าน → สถานที่ → จุดขาย |
| ทีมศูนย์การค้าและเจ้าของสินทรัพย์ | เทียบ tenant mix ของพื้นที่ตนกับพื้นที่เทียบเคียง | โปรไฟล์ย่าน → บุคลิกตามกลุ่มแบรนด์ → แบรนด์เฉพาะ/ร่วม |
| นักวิเคราะห์และที่ปรึกษา | อธิบายความต่างของทำเลด้วยข้อมูลที่ตรวจกลับได้ | กราฟเปรียบเทียบ → ตาราง → แหล่งข้อมูลรายรายการ |

การทำงานเร็วขึ้นหรือเลือกทำเลได้ดีขึ้นเป็นผลที่ต้องวัดกับผู้ใช้ ไม่ใช่ผลที่ผลิตภัณฑ์พิสูจน์แล้ว

## สิ่งที่อยู่ในขอบเขต

ข้อมูลครอบคลุมประเทศไทย รวม luxury designers, fine jewellery, watches, upscale streetwear, Thai designers, curated retailers และกลุ่มขยาย beauty/fragrance กับ accessible premium ที่กรองแยกได้ หน่วยข้อมูลคือ **brand–point-of-sale observation**: หนึ่งรายการต่อหนึ่งหมุด ไม่รวมหมุด ไม่นับเป็นหน้าร้านอิสระ พิกัดต้นทาง สถานะ และประวัติคงเดิมเสมอ

| ชั้นข้อมูล | ไฟล์ | บทบาท |
|---|---|---|
| แบรนด์–จุดขาย | `data/luxury.json` | ตัวตน สถานะ วันที่ แหล่งข้อมูล พิกัด รูปแบบร้าน host |
| ย่าน | `data/neighborhoods.geojson` | แกนย่านเชิงวิเคราะห์ 10 ย่าน polygon คงที่ priority และ ID คงที่ |
| อาคาร | `data/venue-buildings.geojson` | รูปทรงอาคารที่ตั้งและ building parts พร้อมที่มาความสูง |
| อัตลักษณ์แบรนด์ | `data/brand-logos.json`, `assets/brand-logos.svg` | โลโก้ต้นฉบับที่อนุมัติและ alias |

ค่าเริ่มต้นใช้ cohort `refresh` (market_refresh ยกเว้น permanently closed และ closure_conflict_review) ประวัติเดิมและรายการปิดถาวรยังเลือกดูได้ รายการที่ไม่มีพิกัดอยู่ในตารางและจำนวน แต่ไม่สร้างตำแหน่งขึ้นใหม่

## ขอบเขตข้อมูลสามชั้นที่ทุกมุมมองต้องใช้ร่วมกัน

สัญญานี้เป็นหัวใจของรุ่น 0.2 และอยู่ใน `js/app.js`:

| ชั้น | นิยาม | ใครใช้ |
|---|---|---|
| `scopeRows` | รายการหลังตัวกรอง search/cohort/segment/province/channel/venue **ก่อน** เลือกย่านหรือ focus | Aha (ตัวหาร), choropleth, กราฟเปรียบเทียบ, โปรไฟล์ย่าน (ฐานเทียบเฉพาะ/ร่วม), จุดบริบทบนแผนที่ |
| `baseRows` | `scopeRows` ที่แคบลงด้วยย่านที่เลือก | อันดับย่านในแผง, Aha เมื่อเลือกย่าน |
| `rows` | `baseRows` ที่แคบลงด้วย focus “สำรวจ 3 ย่าน” | หมุดแบบละเอียด ตัวเลขรวม ตาราง อาคาร 3D |

เหตุผล: การเลือกย่านหนึ่งย่านต้องไม่ทำให้ “แบรนด์เฉพาะย่าน” กลายเป็น 100% และกราฟเปรียบเทียบต้องยังเทียบทุกย่านในตัวกรองได้ แผนที่จะบอกผู้ใช้ด้วยคำอธิบาย `… · เทียบทุกย่าน ไม่รวมการเลือกย่าน` ทุกครั้งที่สองขอบเขตต่างกัน

## Aha แรก: ย่านก่อนสถานที่

เมื่อข้อมูลพร้อม แผงอ่านข้อมูลแสดงตัวเลขเด่นหนึ่งค่า: **สัดส่วนแบรนด์ไม่ซ้ำที่อยู่ใน 3 ย่านอันดับต้น** พร้อมชื่อย่าน ตัวเศษ/ตัวหาร จำนวนจุดขาย ข้อค้นพบรองเรื่องย่านที่มีแบรนด์เฉพาะมากที่สุด และปุ่ม “สำรวจ 3 ย่านนี้” ถัดลงมาคืออันดับย่านทั้งหมดแบบแท่งซึ่งใช้สีระดับเดียวกับแผนที่ ห้ามใส่ชื่อย่านหรือเปอร์เซ็นต์ตายตัวใน markup

สูตรอยู่ใน `js/area-insight.js#summarizeAreaInsight`: เลือกสูงสุด 3 ย่าน เรียงแบรนด์ไม่ซ้ำ → จุดขาย → stable ID ตัวเศษคือ union ของแบรนด์ใน 3 ย่าน ตัวหารคือแบรนด์ไม่ซ้ำทั้งหมดใน `baseRows` รวมรายการนอกขอบเขต ข้อค้นพบรองใช้ `js/profile-model.js#buildOverviewInsights` บน `baseRows`

เมื่อไม่มีย่านใดมีจุดขาย (เช่น กรองเฉพาะภูเก็ต) Aha ต้องบอกว่ารายการอยู่นอกแกนย่านที่นิยามไว้ แล้วให้อันดับสถานที่ (`rankVenues`) แทน ไม่สรุปว่าไม่มีย่านหรือตลาด เมื่อไม่พบรายการเลยต้องบอกว่าไม่พบตามตัวกรอง พร้อมทางล้างตัวกรอง

## แผนที่: focus + quiet context

หลักการจากเจ้าของผลิตภัณฑ์ (22 ตุลาคม 2569): **แสดงรายละเอียดเฉพาะส่วนที่กำลัง focus ส่วนที่ไม่สำคัญให้เงียบ**

| สถานะ | ส่วนที่ focus | ส่วนบริบท (quiet) |
|---|---|---|
| ภาพรวม (ไม่เลือกอะไร) | ทุกย่านระบายสีตามแบรนด์ไม่ซ้ำ (LDS `count` 5 ระดับ) ป้ายชื่อ + ตัวนับ | หมุดเป็นจุดเล็กมาก ไม่มีโลโก้ต่ำกว่า zoom 13.5 |
| สำรวจ 3 ย่าน | 3 ย่านคงสี เส้นขอบเน้น หมุดสีประเภท โลโก้ | ย่านอื่นเหลือเส้นขอบบาง ป้ายจาง รายการนอก focus เป็นจุดสีเทาเล็ก ไม่มีโลโก้ ไม่อยู่ในลำดับคีย์บอร์ด |
| เลือกย่านเดียว | ย่านนั้นคงสี (ต่ำกว่า zoom 14.5) เส้นขอบเลือก อาคาร 3D หมุดสีประเภท โลโก้ | เหมือนข้างต้น |
| เลือกร้าน | หมุดที่เลือกมีวงเน้น เส้นชี้พิกัดต้นทาง popup บนเดสก์ท็อป | ตาม focus ปัจจุบัน |

กติกาที่ต้องรักษา:

- Choropleth ใช้ค่า HEX ของ LDS `count` ชุดเดียวกันทั้งสองธีม fill opacity 1 วางใต้ชั้นถนนของ basemap ตัดการแสดง fill ที่ zoom ≥ 14.5 แบบสวิตช์ ไม่ใช้ opacity ไล่ระดับ (DATAVIZ-03)
- ค่าเป็น equal-interval 5 ระดับจากค่าสูงสุดของ `scopeRows` ประกาศช่วงในคำอธิบาย ย่านที่นิยามไว้แต่ไม่พบแบรนด์เป็น `measured_zero` (fill ต่ำสุด + เส้นขอบศูนย์) พื้นที่นอกย่านคือ `out_of_scope` ไม่ระบายสี (EVID-05)
- หนึ่งหมุดต่อหนึ่งรายการ ไม่มี cluster; co-location ใช้ slot บนจอภายในรัศมีจำกัดและเส้นชี้กลับพิกัดต้นทาง; โลโก้สูงสุด 250 และแบรนด์ต่างกันได้โอกาสก่อน
- อาคารที่ตั้งใช้สี `map.activeLayer` ไม่ใช้สีชุด categorical เพื่อไม่ชนกับสีประเภทแบรนด์
- ไม่ย้ายพิกัดร้านเพื่อให้ตรงอาคารหรือป้าย

## แผงอ่านข้อมูล (reading panel)

แผงด้านขวา (เดสก์ท็อป) หรือ bottom sheet (มือถือแนวตั้ง) มีสี่โหมดและปุ่มย้อนกลับ ทุกปุ่มส่ง `data-action` เดียวกัน (`js/panel.js`)

| โหมด | เนื้อหา | เข้าได้จาก |
|---|---|---|
| overview | Aha, ตัวเลขรวม, อันดับย่าน (หรืออันดับสถานที่เมื่อไม่มีย่าน) | ค่าเริ่มต้น, ย้อนกลับ, ล้างตัวกรอง |
| neighborhood | อันดับ ชื่อ ตัวเลข บุคลิกตามกลุ่มแบรนด์ สถานที่ในย่าน แบรนด์เฉพาะ/ร่วม (ชิปโลโก้ กดค้นหาได้) ขอบเขตที่ใช้และแหล่งอ้างอิง | ป้ายบนแผนที่, อันดับ, กราฟ, ตัวกรองย่าน, URL `?neighborhood=` |
| venue | ชื่อ ประเภท ย่าน ตัวเลข GLA ที่รายงาน กลุ่มแบรนด์ รายการจุดขาย | สถานที่ในย่าน, อาคาร 3D หลายร้าน, URL `?place=` |
| store | โลโก้ กลุ่ม สถานะจริง สถานที่ ย่าน รูปแบบ พิกัด + ระดับความแม่น วันที่ตรวจ หลักฐาน จุดขายอื่นของแบรนด์ | หมุด, ตาราง, รายการในสถานที่, URL `?store=` |

ตัวกรองยุบอยู่ใน disclosure “ตัวกรอง” พร้อมตัวนับ และมีชิปตัวกรองที่ใช้อยู่ให้ล้างทีละตัว ช่องค้นหาอยู่บนสุดเสมอ ระดับความแม่นพิกัดอ่านจาก `geometryRole/geometryStatus` ด้วย `describeGeometry` ห้ามยกระดับจุดตัวแทนอาคารเป็นจุดร้าน

## กราฟเปรียบเทียบย่าน

ถาดด้านล่างของแผนที่ (ย่อเป็นค่าเริ่มต้น) มีสามมุมมอง วาดด้วย HTML/SVG ไม่มี vendor ทุก mark เป็น `<button>` จริง

| key | คำถาม | การเข้ารหัส | สี |
|---|---|---|---|
| `centers` (อันดับ) | ย่านใดมีแบรนด์หลากหลาย | แท่งแนวนอน แบรนด์ไม่ซ้ำ + จุดขายกำกับ | ระดับ `count` เดียวกับแผนที่ |
| `mix` | ย่านใดเด่นกลุ่มไหน | ตารางตัวเลข ย่าน × กลุ่มแบรนด์ ตัวเลขทุกช่อง | ระดับ `count` ของช่อง (legend แยก) 0 = measured zero มีเส้นขอบศูนย์ |
| `compare` | แบรนด์ของย่านต่างหรือซ้ำกับย่านอื่นเพียงใด | แท่งซ้อน เฉพาะย่าน / พบในย่านอื่นด้วย | series.07 (hexagon) / series.09 (dash) มี cue รูปทรง |

กราฟใช้ `scopeRows` และไฮไลต์ย่านที่เลือก กรณี compare มีน้อยกว่า 2 ย่านแสดงปุ่ม “ดูทุกย่าน” (`resetAreas`) “เฉพาะ/ร่วม” หมายถึงภายในข้อมูลที่เลือกเท่านั้น ไม่ใช่สิทธิ์ขายหรือจำนวนสาขาทั้งประเทศ
