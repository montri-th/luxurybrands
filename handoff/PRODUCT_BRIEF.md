# CityMETER Luxury Brands — Product Brief

รุ่นส่งต่อ 0.1 · ปรับเอกสาร 22 ตุลาคม 2569 · ข้อมูลตรวจถึง 21 ตุลาคม 2569 · ใช้คู่กับ [product-brief.json](product-brief.json)

เอกสารนี้กำหนดประสบการณ์ที่ทีมต้องพัฒนาตามคำสั่งล่าสุด โดยเริ่มอ่านทำเลจาก **ย่าน** แล้วเจาะไปยังศูนย์การค้า อาคาร แบรนด์ และจุดขาย ใช้ [PRODUCT_STATEMENT.md](../PRODUCT_STATEMENT.md) เป็นที่มาของเจตนาผลิตภัณฑ์; ข้อความ UI และลำดับการสำรวจให้ยึด brief ฉบับนี้เมื่อเอกสารเดิมยังอธิบายหน้าจอรุ่นก่อน

## ผลิตภัณฑ์ช่วยตัดสินใจอะไร

**อ่านความต่างของย่านผ่านแบรนด์และจุดขาย แล้วเลือกพื้นที่ที่จะสำรวจต่อ** ผู้ใช้ควรเห็นภาพที่มีความหมายจากข้อมูลทันทีที่เปิดหน้า สามารถเลือกย่าน เปรียบเทียบส่วนผสมแบรนด์ และเปิดร้านที่เกี่ยวข้องได้ต่อเนื่องบนแผนที่เดียว

| ผู้ใช้ | งานที่ต้องทำ | เส้นทางที่ผลิตภัณฑ์รองรับ |
|---|---|---|
| ทีมแบรนด์และขยายสาขา | จัดรายชื่อพื้นที่สำหรับสำรวจ | ภาพรวมย่าน → ส่วนผสมแบรนด์ → จุดขาย |
| ทีมศูนย์การค้าและเจ้าของสินทรัพย์ | เปรียบเทียบพื้นที่และ tenant mix | ย่าน → ศูนย์/อาคาร → แบรนด์และร้าน |
| นักวิเคราะห์และที่ปรึกษา | อธิบายความต่างของทำเลด้วยข้อมูลที่ตรวจกลับได้ | กราฟและแผนที่ขอบเขตเดียวกัน → รายการ → แหล่งข้อมูล |

ปัจจุบันผู้ใช้ต้องเปิด locator หลายแบรนด์ directory ของสถานที่ และตารางรายชื่อแยกกัน จุดมุ่งหมายของ CityMETER คือเชื่อมข้อมูลเหล่านั้นให้สำรวจเป็นพื้นที่ได้ การทำงานเร็วขึ้นหรือเลือกทำเลได้ดีขึ้นเป็นผลที่ต้องวัดกับผู้ใช้ ไม่ใช่ผลธุรกิจที่ผลิตภัณฑ์ได้รับการพิสูจน์แล้ว

## สิ่งที่อยู่ในขอบเขต

ข้อมูลครอบคลุมประเทศไทย รวม luxury designers, fine jewellery, watches, upscale streetwear, Thai designers และ curated retailers รวมร้าน standalone ในย่านต่าง ๆ เช่น ทรงวาด อารีย์ และเจริญกรุง โดยแยก beauty/fragrance และ accessible premium ให้กรองได้

| ชั้นข้อมูล | ไฟล์ที่ใช้งาน | บทบาท |
|---|---|---|
| แบรนด์–จุดขาย | `data/luxury.json` | ตัวตน สถานะ วันที่ แหล่งข้อมูล พิกัด รูปแบบร้าน และ host |
| ย่าน | `data/neighborhoods.geojson` | สมาชิกย่านจากพิกัดต้นทางและ polygon คงที่ |
| อาคาร | `data/venue-buildings.geojson` | รูปทรงและบริบทอาคาร รวม building parts |
| อัตลักษณ์แบรนด์ | `data/brand-logos.json`, `assets/brand-logos.svg` | จับคู่ชื่อแบรนด์กับภาพต้นฉบับและ alias ที่อนุมัติ |

หน่วยข้อมูลคือ **brand–point of sale observation** คำย่อ “1 store 1 pin” ในงานพัฒนานี้หมายถึงหนึ่งรายการจุดขายต่อหนึ่งหมุด ไม่เปลี่ยนเป็นการนับหน้าร้านอิสระ พิกัดต้นทาง สถานะ และประวัติต้องคงเดิม การจัดหมุดให้เลือกได้เป็นการจัดตำแหน่งบนหน้าจอ

ค่าเริ่มต้นใช้ `market_refresh` โดยแยก `permanently closed` และ `closure_conflict_review` ตาม `filterRows()` รายการปิดถาวรและประวัติยังเลือกดูได้ การปิดตามเวลาทำการห้ามเปลี่ยนเป็นปิดถาวรเอง รายการที่ไม่มีพิกัดยังอยู่ในตารางและจำนวนที่เลือก แต่ไม่สร้างตำแหน่งขึ้นใหม่

## Aha แรก: ย่านก่อนสถานที่

เมื่อข้อมูลพร้อม แสดงประโยคสรุปที่คำนวณจากชุดข้อมูลที่เลือก เช่น ย่านที่มีแบรนด์หลากหลายอันดับต้น พร้อมชื่อย่าน ตัวเลข และปุ่มสำรวจต่อ ห้ามใส่เปอร์เซ็นต์หรือรายชื่อย่านตายตัวใน markup

สูตรที่เชื่อมใน source ล่าสุดอยู่ใน `js/area-insight.js`: เลือกสูงสุด 3 ย่าน เรียงแบรนด์ไม่ซ้ำมากไปน้อย แล้วจำนวน POS และ stable ID ตัวเศษใช้ union ของชื่อแบรนด์ในย่านที่เลือก ไม่บวกจำนวนแบรนด์แต่ละย่านตรง ๆ ตัวหารเป็นแบรนด์ไม่ซ้ำทั้งหมดใน filtered base rows ก่อน area focus รวมรายการนอกขอบเขตย่านด้วย ค่า snapshot ใน JSON ใช้ตรวจ regression ไม่ใช้เป็นค่าคงที่ของ UI

ลำดับหลักคือ **ภาพรวมย่าน → เลือกย่าน → ดู brand mix/กราฟเปรียบเทียบ → เลือกแบรนด์หรือจุดขาย → อ่านรายละเอียด** ศูนย์การค้าและอาคารยังเป็นตัวกรองและบริบทสำหรับเจาะต่อ ไม่กลับมาเป็นเรื่องนำของ Aha แรก

การเลือกจาก Aha ต้องเป็น committed selection เดียวกับแผนที่ ตัวเลข กราฟ และตาราง มีทางกลับไปดูทั้งหมด และต้องล้างการเลือกพื้นที่เดิมอย่างสอดคล้องกัน ตัวเลขใน Aha ต้องตรงกับสูตร จำนวนย่านที่เลือก และฐานเปรียบเทียบใน machine contract

## ความสามารถที่เชื่อมแล้วและผลตรวจ

| ความสามารถ | สถานะส่งต่อ | หลักฐานและขอบเขต |
|---|---|---|
| ตัวกรองร่วม แผนที่รายจุดขาย ตาราง สถานะ และแหล่งข้อมูล | Implemented; automated และ browser spot checks | Unit suite ผ่าน 51/51; ตรวจการเลือกย่านและจำนวนรายการใน flow ที่ระบุด้านล่าง |
| ไฟล์เปิดจากเครื่อง → เว็บสาธารณะ | Implemented; source/VM checked | ยังไม่ได้ทดสอบการเปิด `file:` โดยตรงใน native Chrome/Safari |
| Data-ready ก่อนแผนที่/กราฟ และ failure/retry | Implemented; source/isolated recovery checks | เป็นหลักฐานเฉพาะกรณีที่ทดสอบ ไม่ใช่ browser fault-injection ครบทุกกรณี |
| Aha ที่นำด้วยศูนย์การค้า | รูปแบบก่อนหน้า; ถูกแทนที่ใน source ล่าสุด | ไม่ใช้เป็น default Aha รอบนี้ |
| Aha ที่นำด้วยย่าน | Implemented; automated และ rendered spot checks | บนมือถือแสดง 3 ย่าน 175 จุดขาย 97 แบรนด์จาก snapshot นี้; ค่า UI คำนวณจริง |
| อันดับย่าน, bubble mix และ exclusive/shared bars | Implemented; automated และ rendered spot checks | IAB 1280 px ธีมมืดแสดงกราฟทั้งสาม; เลือกสยามได้ 64 POS แล้ว compare แสดงเลือกอย่างน้อย 2 ย่านพร้อม reset action |

ผลข้างต้นยืนยัน implementation, automated suite และ rendered spot checks ที่ทำจริง การตรวจ LDS static artifact ผ่าน และ package verifier ผ่าน 9,768 checks แยกจากผลหน้าจอ ไม่สรุปว่า acceptance AC01–AC12 ผ่านครบทั้งหมด การยืนยัน public release/commit/ไฟล์ bundle รอบสุดท้ายให้ดู `handoff-manifest.json` และ release receipt ที่แนบมากับ bundle

กราฟอันดับเป็นแท่งแบรนด์ไม่ซ้ำรายย่าน ส่วน mix เป็น bubble matrix: แถวย่าน คอลัมน์กลุ่มแบรนด์ สีแยกกลุ่ม และพื้นที่วงกลมแปรตามจำนวนแบรนด์ไม่ซ้ำ กราฟ compare เป็นแท่งซ้อนของแบรนด์ที่พบในย่านเดียวกับแบรนด์ที่พบหลายย่าน โดยเทียบทุกย่านที่ได้รับ assignment ใน selected rows ก่อนตัด Top-N เพื่อแสดงผล

เมื่อเหลือน้อยกว่า 2 ย่าน กราฟ compare ต้องให้เลือกอย่างน้อย 2 ย่านและมีปุ่มดูทุกย่านผ่าน action `resetAreas` ไม่สรุปว่าทุกแบรนด์เป็น exclusive จากการเหลือพื้นที่เดียว ความหมาย exclusive/shared ใช้ภายในข้อมูลที่เลือก ไม่แปลงเป็นสิทธิ์ขายเฉพาะหรือคะแนนความหรู

## ภาษาภาพและ LDS

ใช้ LDS **0.9.7 / v0.9.7-owner.1**, `standalone-0.9.7-r1`; normative SHA-256 `d3085cbc0a50195f1cbf0c77b1d77c0d19b84364daf2948eb367348d65432d96` อ้างไฟล์ใช้งานจริงจาก [assets/manifest.json](../assets/manifest.json) และ [brand logo manifest](../assets/brand-logos-manifest.json) ไม่แนบ normative หรือคลัง tokens ทั้งชุดเพิ่มใน handoff

หัวเรื่องใช้ Arvo/IBM Plex Sans Thai Looped ตามภาษา เนื้อหาและ UI ใช้ Bai Jamjuree 400/600 ตัวเลขใช้ JetBrains Mono 400 พร้อม tabular numerals; caption อย่างน้อย 12 px และตรวจข้อความไทยจริงทั้งสองธีม

ไอคอนใช้ Material Symbols Rounded ชุดที่อนุมัติ: outline, `FILL=0`, `wght=300`, `GRAD=0`, `opsz=24` คงน้ำหนักทุกสถานะ ใช้เฉพาะ glyph ที่อยู่ใน subset และมีข้อความกำกับ ห้ามวาด glyph ที่หายหรือยืมไอคอนผิดความหมาย

คง categorical IDs และคู่สีตามบทบาท ห้ามสร้างสูตรเปลี่ยนสีข้อมูลในธีมมืด ไม่มี decorative brackets หรือแถบสีซ้ายบนเมนู การ์ด หรือ callout ต้องมี keyboard focus และรองรับ reduced motion
