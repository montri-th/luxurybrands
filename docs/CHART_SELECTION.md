# กราฟเปรียบเทียบย่าน

รุ่น 0.2 (22 ตุลาคม 2569) วาดกราฟด้วย HTML/SVG ใน `js/charts.js` โดยไม่มีไลบรารีภายนอก โมเดลตัวเลขอยู่ใน `js/chart-model.js` ทุก mark เป็น `<button>` จริง จึงใช้เมาส์ คีย์บอร์ด และ screen reader ได้เท่ากัน ไม่มี animation ไม่มีข้อมูลตัวอย่างปะปน

| มุมมอง / key | คำถามที่ตอบ | รูปแบบ | สี | การเลือก |
| --- | --- | --- | --- | --- |
| ย่านที่มีแบรนด์ / `centers` | ย่านใดมีแบรนด์ไม่ซ้ำมากที่สุดในตัวกรอง | แท่งแนวนอนเริ่มที่ 0 ความยาว = แบรนด์ไม่ซ้ำ ตัวเลขปลายแท่ง + จำนวนจุดขายกำกับ | ระดับ `count` ของย่าน (ชุดเดียวกับแผนที่) | กดแท่งเพื่อเปิดย่าน |
| บุคลิกของย่าน / `mix` | กลุ่มแบรนด์ใดพบในย่านใด มากน้อยต่างกันอย่างไร | ตารางตัวเลข ย่าน × กลุ่มแบรนด์ ตัวเลขทุกช่อง **ทุกช่องขนาดเท่ากัน** (`table-layout: fixed` + `<colgroup>`) | พื้นช่องตามระดับ `count` ของค่าในช่อง (legend แยกใต้ตาราง) ช่อง 0 เป็น measured zero มีเส้นขอบศูนย์ | กดช่องหรือชื่อย่าน |
| แบรนด์เฉพาะ / ร่วม / `compare` | แบรนด์ของแต่ละย่านมีกี่แบรนด์ที่พบในย่านอื่นด้วย | แท่งซ้อนสองส่วน รวมเป็นแบรนด์ไม่ซ้ำของย่าน ตัวเลขในแต่ละส่วน | series.07 (cue hexagon) = เฉพาะย่านนี้ · series.09 (cue dash) = พบในย่านอื่นด้วย | กดแท่งเพื่อเปิดย่าน |

เหตุผลที่เปลี่ยนจาก bubble matrix เป็นตารางตัวเลข: วงกลมเล็กอ่านค่าไม่ได้และตัวเลขโผล่ไม่สม่ำเสมอ ตารางตัวเลขให้ค่าแน่นอนทุกช่อง non-color cue คือตัวเลขเอง และสีเป็นเพียงตัวช่วยเปรียบเทียบตาม DATAVIZ-02/03 (HEX เดียวกันสองธีม)

รุ่น 0.3 แก้ปัญหาที่เจ้าของผลิตภัณฑ์พบ (22 ต.ค. 2569): ช่องกว้างไม่เท่ากันเพราะความกว้างคอลัมน์ขึ้นกับความยาวหัวคอลัมน์และค่าในช่อง ทำให้ช่อง “2” กว้างกว่าช่อง “15” และดูเหมือนขนาดมีความหมาย ตอนนี้ตารางใช้ `table-layout: fixed`, `<colgroup>` ที่ประกาศจำนวนคอลัมน์ (`--matrix-columns`) และช่องสูง 36 px เท่ากันทุกช่อง caption ใต้ตารางระบุว่า **ขนาดช่องไม่มีความหมาย** ตัวเลขและระดับสีเท่านั้นที่เข้ารหัสค่า (INV18)

## ความหมายของจำนวน

`buildNeighborhoodChartModel(rows, neighborhoods, segments)` รับ `scopeRows` (ตัวกรองก่อนการเลือกย่าน) และใช้ `summarizeNeighborhoods` / `assignNeighborhood` เป็นเจ้าของการจัดพื้นที่ จุดหนึ่งอยู่ได้หนึ่งย่านตาม polygon และ priority ที่ตรึงไว้

- **แบรนด์ไม่ซ้ำ:** Set ของชื่อแบรนด์ในแต่ละขอบเขต จุดขายหลายรายการของแบรนด์เดียวกันไม่เพิ่มจำนวน
- **รายการจุดขาย:** จำนวน observation rows ตาม grain ของ dataset
- **เฉพาะย่านนี้ / พบในย่านอื่นด้วย:** เทียบทุกย่านที่มีจุดขายใน `scopeRows` ก่อนตัดอันดับที่แสดง ไม่ใช่เฉพาะย่านที่เลือก
- จุดนอก polygon ไม่ถูกเดาย่าน และยังอยู่ใน `totalPos` / `totalBrands`
- ย่านที่เลือกบนแผนที่ถูกไฮไลต์ (`selectedAreaId`) แต่ไม่ตัดย่านอื่นออกจากกราฟ คำอธิบายกำกับว่า “เทียบทุกย่าน ไม่รวมการเลือกย่าน”

คำว่าเฉพาะไม่ใช่ข้อสรุปว่าแบรนด์มีแห่งเดียวในประเทศไทย และไม่ยืนยันผลธุรกิจ ยอดขาย อุปสงค์ หรือความครบถ้วนของตลาด

## สีและระดับ

ระดับสีมาจาก `js/scales.js#buildCountClasses`: equal-interval สูงสุด 5 ระดับจากค่าสูงสุดในชุดที่วาด ช่วงเป็นจำนวนเต็มปิดทั้งสองด้าน ตัวเลขที่แสดงกับระดับที่ระบายจึงตรงกันเสมอ กราฟอันดับใช้ค่าสูงสุดของย่าน ส่วนตารางใช้ค่าสูงสุดของช่อง จึงมี legend แยกของตัวเอง สีตัวอักษรบนพื้นช่องเลือกจาก `inkFor` ให้ได้ contrast ≥ 4.5:1 (ตรวจใน `tests/scales.test.js`)

## Integration contract

`renderInsightChart({elementId, view, rows, segments, neighborhoods, theme, selectedAreaId}, onSelect)` คืน disposer; ทุก mark ส่ง `{type:'neighborhood', id}`; กรณี compare มีน้อยกว่า 2 ย่านแสดงข้อความและปุ่ม “ดูทุกย่าน” ที่ส่ง `{type:'resetAreas'}` แอปเป็นผู้รักษาตัวกรองอื่น

## การตรวจ

`tests/chart-model.test.js` ตรวจค่าจริงเริ่มต้น 345 observations / 113 แบรนด์, 10 ย่านที่มีข้อมูล, 244 rows ในขอบเขต; อันดับต้นคือสยาม 57 แบรนด์ / 64 rows, พร้อมพงษ์ 51 / 56 และชิดลม–เพลินจิต 45 / 55; duplicate POS, union/overlap ก่อนตัดอันดับ, ทุก cell รวม zero, nonmutation `tests/scales.test.js` ตรวจ LUT, thresholds และ contrast ผลหน้าจอจริง (ความอ่านง่าย คลิก คีย์บอร์ด ธีม) บันทึกใน `handoff/VERIFICATION.md` แยกจาก unit tests
